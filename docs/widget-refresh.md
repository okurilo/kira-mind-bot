# Обновление сохранённых виджетов

Реализует запрос мобильного агента от 2026-11-08. Это отдельное чтение источника, не ход разговора. Телефон сам запрашивает карточки при открытии AR-комнаты и появлении избранного на экране; переписка показывает исходный снимок. Сервер не запускает polling по таймеру и не делает новые записи в истории, памяти, Telegram, задачах или UI-events. Существующий v2 `ui.target` остаётся отдельным явным ходом диалога.

## Согласование и сообщения

`GET /api/v1/capabilities` → `generativeUi.refresh:{enabled:true,maxItems:10}`. При `KIRA_UI_REFRESH_ENABLED=false` ключ отсутствует, маршрут возвращает404. Клиент без capability ничего нового не отправляет.

В `/messages`, `/actions`, `/photos` и исполняемом `/scene/turns`:

```json
{"ui":{"enabled":true,"catalogId":"urn:kira:ui:catalog:1","refresh":true}}
```

Поддерживаются оба каталога, включая v1 без расширения его строгой схемы. Разрешение действует на один ход и входит в fingerprint квитанции. У исходного сообщения рядом с `ui`, **не внутри снимка**, может быть:

```json
{"uiRefresh":{"token":"OPAQUE_REFRESH_TOKEN","kind":"data","asOf":"2041-04-12T19:00:00Z","minIntervalSeconds":600}}
```

Токен — непрозрачный printable ASCII U+0021…U+007E, ≤512 символов, связан с владельцем и surfaceId. Он разрешает только чтение этого рецепта, требует Bearer того же аккаунта и не является actionToken. Первоначальный токен живёт 30 суток; новое поколение при изменении данных продлевает срок на 30 суток. Отзыв устройства, удаление/явная замена поверхности и удаление аккаунта могут прекратить доступ раньше. Прежний токен восстанавливает актуальное поколение из кеша при потере ответа или на другом устройстве. Клиент токен не разбирает.

`kind=data` получает интервал600 секунд, `kind=search` —3600. asOf означает время данных из источника; если у первоначального поискового ответа точного времени нет, поле опускается. Генерация и время HTTP-запроса его не заменяют. Успешное повторное получение всегда требует подтверждённого UTC asOf. Без источника/рецепта, без opt-in или для статического плана uiRefresh отсутствует. `/history` сохраняет исходные ui и uiRefresh, включая для v2; он не показывает пассивно обновлённые цифры.

## Пакетное чтение

```http
POST /api/v1/ui/refresh
Authorization: Bearer <account-access-token>
Idempotency-Key: refresh-visible-001
Content-Type: application/json
```

```json
{"items":[{"token":"OPAQUE_REFRESH_TOKEN","surfaceId":"kira_11111111111141118111111111111111"}],"ui":{"enabled":true,"catalogId":"urn:kira:ui:catalog:1","refresh":true}}
```

1–10 разных surfaceId, без дополнительных полей. Тот же ключ требует того же тела. Каталог должен совпадать с сохранённым снимком. `ui.target` здесь не принимается. Ответ200 содержит `results` в порядке items:

| status | Поля помимо surfaceId | Поведение |
|---|---|---|
| updated | ui, uiRefresh | Полный проверенный снимок, тот же surfaceId, те же ID/макет; атомарно заменить в избранном/AR, сохранить новый токен |
| unchanged | uiRefresh | Обновить метку данных/токен, оставить значения |
| tooEarly | retryAfterSeconds | Не обращаться до указанного интервала; сюда входит остановка по фоновому бюджету |
| gone | — | Неизвестный, чужой, истёкший или отозванный токен, несовпадение поверхности/каталога; прекратить обновление |
| failed | — | Источник не подтвердился, поменял показатель/единицы, недоступен или вернул некорректные данные; оставить старый снимок |

Повтор квитанции не читает источник. Старое поколение токена может получить `updated` из кеша даже до интервала: это восстановление пропущенной доставки, а не новый поиск. Новое чтение с текущим поколением ограничено интервалом, включая ошибки источника. Параллельные запросы объединяются долговечной lease; потеря процесса не вызывает немедленного повтора.

Ошибки имеют общий формат `{"error":{"code":"…","message":"…","retryAfterSeconds":60},"requestId":"…"}`. 401 — авторизация, 404 — выключенный/старый сервер, 400 — тело, 413 — размер/число items, 409 idempotency_conflict — изменённое тело, 429 — 30 новых запросов/минуту на владельца (есть Retry-After и retryAfterSeconds), 503 — недоступное хранилище/квитанции. Общие лимиты REST продолжают действовать. Отказ до исполнения не оставляет неопределённую квитанцию; успешный ответ кешируется обычным durable механизмом API.

Каждое реальное чтение источника резервирует отдельную **фоновую** AccountQuota-задачу. Оно не наследует разговорный бюджет HTTP-запроса. Экономия, автономность, согласие AI и ограничения аккаунта действуют. Исчерпанный фон →tooEarly, без молчаливого перехода в разговорный пул. Восстановление из кеша и tooEarly до источника не запускают AI-задачу.

## Что хранится на сервере

Фактический source binding фиксируется в request-local AsyncLocalStorage только во время разрешённого хода. Текст вопроса и догадка compositor-а сами по себе не создают рецепт. Compositor в уже существующем вызове может выбрать реальный источник и до24 изменяемых листьев: Text.text, Metric.value/detail/tone, Progress.value/detail, ячейки/матрица Table и существующие подписи/числа/ряды Chart. Массивы сохраняют размеры и тип каждого элемента; пересекающиеся slots запрещены. ID, ссылки child/children, колонки, число строк/точек, единицы/объект и остальные поля фиксированы.

При data initial value обязан точно совпасть с полем API либо с литеральным prefix+String(value)+suffix. При search сохраняются исходный публичный запрос, объект/показатель, точный URL источника, описания и типы слотов. Сервер не хранит в рецепте персону, историю чата, память или credentials. Рецепты живут в owner-scoped bot_settings отдельно от короткой истории UI: до512 активных, без вытеснения действующего30-дневного токена. При достижении предела новый ответ остаётся обычным виджетом без uiRefresh. Очистка истёкших записей использует компактный индекс, не загружает все макеты.

Повтор заполняет только слоты. Полный снимок снова проходит runtime-валидацию, 32 КиБ и прежние лимиты. Серверные Button/Checklist actions, формы и Image не получают пассивный рецепт; openUrl из исходного подтверждённого источника разрешён. Compositor знает об ограничении и может сделать пассивную карточку, сохранив обычные кнопки текстового ответа отдельно.

Для v2 сервер увеличивает revision при изменении значений и сохраняет текущий presentation cache, без записи UI-event и без изменения сообщения истории. Ответ refresh всегда **полный снимок**: его можно атомарно применить при пропущенных поколениях; это не incremental patch. Явное последующее ui.target использует текущую revision и отзывает прежний пассивный рецепт. AR-положение и размер остаются на клиенте, widgetPlacement заново не генерируется.

## API-источники без LLM

В проекте внешние сведения могут приходить через web search или MCP; название вопроса не делает их API-источником. Для режима data оператор явно перечисляет повторяемые read-инструменты **без LLM** в конфигурации MCP:

```json
{"servers":{"example":{"description":"Прямые наблюдения API","transport":"jsonrpc","url":"https://example.org/mcp","tools":{"observation":"read"},"refreshTools":["observation"]}}}
```

Только read, без external, дубликатов или неизвестных имён. Не изменяй текущую приватную конфигурацию автоматически. Такой инструмент в `structuredContent.uiRefresh` возвращает:

```json
{"identity":"station:example|temperature|celsius|current","asOf":"2041-04-12T19:00:00Z","sources":[{"label":"Источник","url":"https://example.org/observations"}],"values":{"temperature":18}}
```

identity (≤500) стабильно включает объект, показатель, единицы, разрешение и аккаунт/портфель, если он влияет на данные. values —1–64 поля с обычными component ID ключами: scalar либо массив/матрица scalar, без объектов; массивы≤64 элемента, вложенность≤2. Строки≤3000, конечные числа abs≤1e15, boolean; payload≤20КиБ. sources —1–8 HTTPS ссылок. Это приватная адаптерная metadata, в A2UI-клиент она не уходит.

Повтор вызывает **тот же** MCP-инструмент с исходными аргументами и текущими operator-bound fixedArguments; endpoint/transport/fixed identity/effect/разрешение закреплены hash-ом, credentials не сохраняются. Изменение identity, типа поля, источника или конфигурации →failed. Сервер не вызывает модель в data-ветке. Если инструмент использует LLM, не объявляй его refreshTools: по одному удачному результату отсутствие модели не выводится. Сервис без этого контракта остаётся не обновляемым data-источником, без автоматического перевода в search.

## Поисковые источники

Фиксируется успешный фактический web search с provider citation, без повторения памяти/истории/персоны. Контекст диалога не сохраняется в refresh query. Отдельные многоэтапные проверки доступности не объявляются обновляемыми. Search-повтор использует экономный preset gpt-lean и один логический `webSearchReasoning` Responses-вызов с web search и строгой JSON Schema значений, без compositor-а, repair и fallback-цикла. Общая provider policy и учёт usage сохраняются.

Ответ модели содержит только found/asOf/sourceUrl/values. URL должен точно совпасть с сохранённым и присутствовать в новых provider citations; список ключей/типы совпадают со слотами. Время не может быть старше предыдущего. Неподтверждённый источник, неизвестный момент данных, другой показатель или попытка прислать макет дают failed. Структурная проверка не является доказательством истинности внешней страницы; смысл извлечения дополнительно проверяется синтетическим eval.

При структурированном JSON URL подтверждается также полным списком реально использованных источников `web_search_call.action.sources`, без требования вставлять prose-сноски в значения. Совместимость текущего SDK проекта сохраняет `web_search_preview`: [OpenAI Docs](https://developers.openai.com/api/docs/guides/tools-web-search) продолжает описывать этот legacy-интерфейс; правила JSON Schema и границ массивов — в [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses). Если изменилось только время данных, оно обновляется в sidecar; прежняя revision не получает другое содержимое снимка.
