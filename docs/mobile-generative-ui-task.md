# Задание агенту мобильного приложения: генеративные виджеты Киры

Реализуй нативный renderer ограниченного профиля **A2UI 1.0 / `urn:kira:ui:catalog:1`**. Серверная реализация находится в этой ветке; приложение разрабатывается отдельно. Основной контракт: [generative-ui.md](generative-ui.md), [JSON Schema](generative-ui.schema.json), `api/openapi.json` и `generative-ui/contracts.ts`. Не реализуй весь A2UI и не считай basic catalog совместимым с каталогом Киры.

## Интеграция

1. Прочитай авторизованный `GET /api/v1/capabilities`, проверь `generativeUi.protocol`, `version`, `catalogId`. Включай opt-in только после реализации всех компонентов текущего каталога. Если поддержка отсутствует, работай через существующий текстовый протокол.
2. На каждом поддерживаемом запросе `/messages`, `/photos`, `/actions`, исполняемом `/scene/turns` передавай `ui: {"enabled":true,"catalogId":"urn:kira:ui:catalog:1"}`. Это capability поверхности, не настройка аккаунта. Для переключателя «Только текст» убирай ui либо передавай `{"enabled":false}`. User-agent и текст вопроса не заменяют флаг.
3. Ответ читай как прежний `messages[]`. Показывай текст, озвучивай **только text**, никогда JSON. Если у сообщения есть известный `ui`, рендери snapshot рядом с текстом. Отсутствие ui — нормальный ответ. Неподдерживаемая версия/сбой валидации оставляет текст видимым.
4. Проверяй весь payload до монтирования: лимит 32 КиБ, allowlist полей/компонентов, одно дерево root, глубина/число узлов, уникальные ID, ссылки, таблицы и графики. Не исполняй HTML, Markdown, JavaScript, expression/data binding, произвольные `@call` и неизвестные функции. Не загружай каталог или компоненты по catalogId.
5. Примени `ui.messages` последовательно как **один атомарный snapshot**. V1 содержит один `createSurface` с inline components. Кешируй по `message.id`, `surfaceId`; повтор квитанции не добавляет вторую карточку и не повторяет озвучку. Удаляй/заменяй UI вместе с владельцем-сообщением. Rehydrate из `/history`: `role`, `text`, `createdAt`, опциональные `ui` и `id`; сохрани исходный surfaceId.

## Нативный вид

Используй существующие дизайн-токены приложения и системные Dynamic Type/VoiceOver/TalkBack:

- `Column` — вертикальный стек, `Row` — переносимый горизонтальный стек. `gap` сопоставь трём размерам spacing приложения. `Card` — нативная карточка. Корень может быть любым допустимым компонентом.
- `Text` — plain text, `variant` задаёт заголовок/основной текст/подпись. `Divider` — разделитель.
- `Metric` — крупное `value`, рядом `label`, ниже `detail`; семантический tone через палитру приложения, без зависимости от одного цвета.
- `Table` — компактная таблица или карточки строк на узком экране. Подписи колонок остаются доступны скринридеру.
- `Chart` — нативный line/bar/donut. Порядок `labels` соответствует позициям каждого `series.values`, единица — `unit`. Покажи подписи рядов и доступный список/таблицу точек. Без сглаживания, которое создаёт новые значения, и без выдуманного временного шага.
- `Button` — child Text с честной подписью. Кнопки не срабатывают при декодировании, появлении, восстановлении, озвучке или повторе API-квитанции.

Для AR сначала показывай те же виджеты как 2D-панели средствами приложения. Размещение в комнате выбирает телефон. Виджет не должен менять движение персонажа или геометрию сцены.

## Нажатия

У кнопки `action.functionCall` разрешён только `{"@call":"openUrl","args":{"url":"https://..."}}`: проверь схему URL/отсутствие credentials и открой по жесту пользователя штатным браузером. Других функций или автоматических сетевых запросов нет.

Для `action.event.name` **`kira.reply` или `kira.action`** возьми `context.actionToken` и вызови существующий endpoint:

```http
POST /api/v1/actions
Authorization: Bearer <current-session-access-token>
Idempotency-Key: <new-stable-key-for-this-click>
Content-Type: application/json
```

```json
{
  "actionToken": "<opaque-token-from-widget>",
  "ui": {"enabled":true,"catalogId":"urn:kira:ui:catalog:1"}
}
```

Токен не разбирай и не создавай. Не отправляй `surfaceId` вместо токена, callback data, произвольный action name, код или API URL. `kira.reply` уже содержит серверную реплику и обрабатывается как обычный пользовательский ввод; `kira.action` переиспользует подготовленное доменное действие и его подтверждения. Показывай состояние ожидания на время запроса, блокируй двойное нажатие. При потере связи повторяй тот же запрос с прежним ключом. Нельзя объявлять действие успешным до ответа сервера.

Действия живут 15 минут и до следующего API-хода. Старые карточки остаются визуально читаемыми, их серверные кнопки отключай после нового хода; при `action_expired` предложи запросить актуальную карточку. Ссылки могут продолжать открываться. Для «Да/Нет» не заменяй выданные кнопки действия собственным строковым подтверждением.

## Повторы и режим ответа

Повтор с прежним `Idempotency-Key` должен сохранять body и `Prefer`, включая ui. Изменение UI-режима требует нового хода и ключа; прежний ход нельзя повторно исполнять ради другой карточки. Использованный actionToken под новым ключом возвращает прежний результат, а изменение его UI-предпочтения может дать `idempotency_conflict`.

V1 виджетов возвращает полный синхронный ответ. Даже если приложение отправило `Prefer: respond-async`, при ui оно не получит `Preference-Applied`; обработай обычный завершённый `messages[]`. Streaming/формы/live charts пока не поддерживаются. Сохрани прежнюю обработку фото, файлов, обычных `buttons` и ошибок API.

## Вопросы для ручной приёмки

| Вопрос | Что проверить |
|---|---|
| «Какая сегодня погода в Амстердаме? Покажи прогноз по часам» | Свежие источники прежнего pipeline; показатели/таблица/график при наличии точек, текст озвучивается отдельно |
| «Что с акциями Apple и Microsoft сегодня? Сравни цену и изменение» | Подписи валют/времени; без выдуманной истории; при недоступном источнике честный текст |
| «Сравни варианты: А — 10 евро за 5 ГБ, Б — 20 евро за 15 ГБ» | Таблица/показатели, адаптация узкого экрана и VoiceOver |
| «Предложи вечерний план: 20 минут чтения и 30 минут прогулки» | Нативная композиция; предложение не считается сохранённой задачей |
| «Покажи следующий день» после прогноза или кнопка с похожей подписью | Быстрый ответ проходит как новый ход, следующий ui требует нового opt-in |
| «Напомни завтра в 10 полить цветы» | Сохраняется прежнее создание/подтверждение напоминания; виджет не вызывает действие сам |
| «Привет!» / «Спасибо» / «Мне грустно, побудь рядом» | Нормальный текстовый ответ, отсутствие ui не выглядит ошибкой |

Точная форма и само наличие карточки выбираются моделью, поэтому приёмка не должна требовать одного layout для одной фразы. Для воспроизводимых UI-тестов используй синтетические snapshots по schema, отдельно проверяй реальный серверный путь.

Автоматизируй: декодирование всех 9 компонентов и 3 видов действий; неверные версии/поля/циклы/лимиты; длинный текст и accessibility; отсутствие ui; повтор HTTP и восстановление истории без дублей/озвучки; истёкшую кнопку; смену аккаунта с очисткой UI/token cache; loss-of-connection/retry без повторного действия; AR-панель без пространственных эффектов.

Готовый результат: нативные виджеты в чате/поддерживаемых поверхностях, неизменный текстовый fallback и TTS, рабочие действия с прежними серверными ограничениями, тесты и несколько скриншотов приёмки на синтетических данных.
