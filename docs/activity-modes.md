# Активность Киры

Общий каталог находится в `ai/activity-modes.json`; `ai/activityModeCatalog.js` применяется API и админкой. Кабинет и мобильный клиент получают названия, описания, состав и пояснения расхода с сервера.

| Ключ | Название | Автоматические функции |
| --- | --- | --- |
| `on_demand` | По моей инициативе | Фоновые функции выключены. Общение, ручные поручения, сохранённая память и обычные напоминания доступны. |
| `memory` | Помнит важное | `deferredFacts`, `memoryConsolidation`, `dialogueDeepReview`: память из разговоров, упорядочивание и полезный дополнительный разбор. |
| `proactive` | Помогает заранее | Всё из `memory`, подсказки из памяти, сохранённые регулярные задачи, дайджест; при доступном личном Telegram — новые сообщения, дневные карточки, вечерний обзор, непрочитанные, сохранённые наблюдения и отслеживаемые группы. |
| `maximum` | Максимальный | Все функции из текущего каталога, включая изучение истории личных переписок и жизнь/развитие персонажа с проверкой внешних событий. |
| `custom` | Настроить под себя | Собственный набор переключателей. |

Выбор не удаляет память, задачи или расписания. Выключенные регулярные AI-задачи приостанавливают автоматическое выполнение. Обычные напоминания остаются отдельным механизмом. Фоновый расход зависит от моделей и объёма работы; стоимость и качество ответа не задаются этим переключателем.

## API

Существующие `GET/PATCH /api/v1/settings` и прокси кабинета `GET/PATCH /api/v1/web/api/settings` сохраняют авторизацию и изоляцию аккаунта. В `GET` добавлены:

```json
{
  "activityMode": "memory",
  "activityModes": [
    {
      "key": "memory",
      "title": "Помнит важное",
      "description": "Дополнительно сохраняет подтверждённые факты из разговоров и упорядочивает память.",
      "benefits": ["Память из разговоров с Кирой", "Упорядочивание фактов и связей", "Дополнительный разбор ответа, когда он полезен"],
      "costNote": "Добавляются фоновые AI-вызовы для работы с памятью.",
      "featureKeys": ["deferredFacts", "memoryConsolidation", "dialogueDeepReview"]
    }
  ]
}
```

Ответ содержит полный каталог, включая `custom` с `featureKeys:null`. Пример показывает одну запись. Старые `budgetMode`, `budgetModes`, `telegram` и `features` сохраняются.

Применение готового режима:

```json
{"activityMode":"proactive"}
```

Сервер разворачивает его во все булевы `background:*` и `BUDGET_MODE=normal` одним PostgreSQL upsert, затем обновляет runtime-кеши. Отдельные запросы на каждую функцию не нужны. Изменения применяются максимум за 5 секунд; уже начатая работа может завершиться. `Idempotency-Key` для PATCH settings не требуется. Можно явно сохранить выбранный набор на паузе: `{"activityMode":"memory","budgetMode":"maximum"}`.

Ручная поправка: `{"activityMode":"custom","background":{"kiraLife":false}}`; прежний формат `{"background":{"kiraLife":false}}` также работает. Пропущенные флаги сохраняются. Готовый режим и `background` в одном запросе запрещены. `custom` без непустого `background`, неизвестные режимы/ключи и не-булевы флаги дают `400 invalid_settings`.

Текущий `activityMode` вычисляется из сохранённых флагов. Если они совпадают с готовым набором, возвращается его ключ; иначе `custom`. Дополнительного marker/store нет. GET не изменяет настройки, старые установки и новые аккаунты не переключаются автоматически.

## Пауза и доступность

`activityMode=maximum` — максимальная активность. Старый `budgetMode=maximum` остаётся паузой платного AI-фона и не переименовывается в протоколе. Пауза сохраняет выбранные флаги; включённые бесплатные дайджест/напоминания о непрочитанных и обычные напоминания могут продолжать работать. Применение готового режима снимает эту паузу, если PATCH явно не задаёт её снова.

У `features` остаются сохранённый `enabled`, локальная доступность `effective` и причина `blockedBy`: `budget`, `telegram` либо ключ зависимости. Согласие на AI, ограничения и квоты аккаунта, центральное `autonomousAiEnabled` и подтверждения внешних действий продолжают проверяться отдельно. Режим не выдаёт эти разрешения и не подключает личный Telegram. Для нового публичного аккаунта центральный автономный AI по-прежнему выключен до отдельного разрешения; интерфейс не должен обещать запуск только по `effective`.

Админка получает те же `activityMode/activityModes` в `GET /api/background-features`; готовый набор сохраняется `POST /api/background-features` с `{"activityMode":"memory"}`. Существующие POST одной функции и `/api/budget-mode` совместимы.
