# Квоты общения и фоновой работы

У аккаунта два независимых суточных бюджета. Общение и явные поручения по умолчанию получают 20 задач, фон — 60. Изображения сохраняют отдельный лимит 1 в сутки и одновременно используют единицу своего основного бюджета. Обновление — в 00:00 UTC. Это лимиты задач, а не токенов, стоимости или отдельных сообщений модели.

Одна задача — исходное поручение или один ограниченный фоновый запуск: серия сообщений для рефлексии, цикл консолидации памяти, обзор переписок, выполнение повторяемого задания. Классификация, поиск, анализ, модерация, инструменты, ответ и технические повторы внутри неё используют один серверный ID. Обязательный отложенный ответ, уточнение и проверенное подтверждение продолжают исходную задачу; новый вопрос начинает новую. Необязательные подсказки, отложенное извлечение фактов и самостоятельные обзоры имеют собственные фоновые ID.

Резерв становится расходом перед первым разрешённым внешним вызовом. Если ничего не отправлено, резерв освобождается; неизвестный результат отправки расход не возвращает. Повтор той же задачи и переход суток не списывают её второй раз. Пул уже начатой задачи менять нельзя. Дополнительный предел 128 внешних AI-вызовов на задачу ограничивает её длину независимо от единицы расхода; модерация тоже входит в этот предел.

Фоновая задача проверяет свой резерв до удаления сообщений из буфера и продвижения позиции чтения. При исчерпании фоновой квоты источник остаётся для следующего запуска. Повторяемые задания откладываются до обновления квоты без постоянного отключения; необязательное дополнение к уже данному ответу может быть пропущено. Сохранение обычного напоминания и его таймер не требуют AI, а необязательная запись в память использует фон отдельно.

Исчерпанный фон не использует бюджет общения. Диалог сохраняет доступ к своему остатку. Если исчерпано общение, Кира явно сообщает об этом; расход фона сам по себе к такому отказу не приводит. Проверки согласия, автономности и ограничений аккаунта продолжают действовать перед каждым внешним вызовом.

Админка и портал показывают для общения, фона и изображений лимит, расход, резерв, остаток и время обновления. Кнопка обновления не сохраняет и не стирает черновик режима. Ошибка чтения показывается явно. Пауза фона по квоте не изменяет выбранный режим и переключатели функций.

Серверные переменные: `KIRA_PUBLIC_DIALOGUE_DAILY_LIMIT=20` (fallback: прежняя `KIRA_PUBLIC_AI_DAILY_LIMIT`), `KIRA_PUBLIC_BACKGROUND_DAILY_LIMIT=60`, `KIRA_PUBLIC_IMAGE_DAILY_LIMIT=1`, `KIRA_PUBLIC_AI_TASK_MAX_CALLS=128`. Лимиты нельзя выбрать в пользовательском запросе.

API `/api/v1/account/quota` и snapshot аккаунта сохраняют `version:1`: добавлены `dialogue`, `background`, `legacyAi`, прежнее `ai` равно `dialogue`. Каждый основной бюджет содержит `limit`, `used`, `reserved`, `remaining`; общие `day`, `resetAt` используют UTC. Прежние расходы невозможно достоверно разделить по источнику, поэтому миграция сохраняет их отдельно в `legacyAi`, не вычитая из новых бюджетов. Ранее списанные receipts не оплачиваются повторно. Миграция повторяемая и не сбрасывает новые счётчики.

Админка читает только квоты текущего аккаунта через каноническую авторизацию. Приватный вход использует серверный runtime Bearer, который не выдаётся браузеру. Для автономной установки без сервиса аккаунтов панель явно сообщает об отсутствии аккаунтных квот.
