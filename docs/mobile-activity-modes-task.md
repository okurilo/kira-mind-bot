# Задача Клоду на MacBook Pro: режимы активности Киры

Владелец утвердил развёрнутые названия и поручил внедрить их в мобильном приложении. Сервер, админка и веб-кабинет используют общий контракт из [activity-modes.md](activity-modes.md), схема — `api/openapi.json` репозитория бота. Нативный клиент находится в checkout KiraMindAvatar на MacBook Pro; работай с его текущим состоянием, не заменяй его копией из старого GitHub snapshot.

## Подготовка

Прочитай `AGENTS.md`, `DESIGN.md`, актуальные DTO API, сервис settings и действующий SwiftUI-экран настроек. Проверь git status и создай отдельную ветку, сохрани чужие незавершённые изменения. Не запускай ещё одну копию Telegram-бота. Адрес сервера возьми из конфигурации приложения; credentials остаются в Keychain и локальной конфигурации.

## Что сделать

1. Замени главный выбор «Экономия AI / Выборочный фон» разделом **«Активность Киры»**. Покажи четыре режима в порядке каталога:
   - **По моей инициативе** — общение и поручения по обращению, обычные напоминания; автоматический фон выключен, сохранённая память доступна.
   - **Помнит важное** — дополнительно сохраняет подтверждённые факты из разговоров, упорядочивает память и при необходимости углубляет разбор.
   - **Помогает заранее** — добавляет подсказки, обзоры и сохранённые задачи по расписанию; Telegram-функции требуют личной сессии.
   - **Максимальный** — весь доступный фон, включая изучение истории переписок и жизнь/развитие персонажа.
2. Используй `GET /api/v1/settings`: новые `activityMode` и `activityModes`. В каталоге запись содержит `key`, `title`, `description`, `benefits`, `costNote`, `featureKeys` (для `custom` — null). Тексты и состав бери с сервера. Ключи стабильны: `on_demand`, `memory`, `proactive`, `maximum`, `custom`. Предусмотри отсутствие полей на прежнем сервере и неизвестные будущие ключи без падения декодирования. Существующий `budgetMode` не переосмысливай.
3. Отдели выбранный черновик от текущего сохранённого режима. Под выбранным вариантом покажи описание, преимущества и пояснение фонового расхода. Применение — явной кнопкой. Не сохраняй по открытию экрана, декодированию GET или смене аккаунта.
4. Готовый режим сохраняй **одним PATCH** `{"activityMode":"memory"}`. Сервер атомарно меняет весь набор функций и снимает паузу AI. Не отправляй 19 запросов по переключателям и не собирай preset вручную на iPhone. После успешного PATCH принимай возвращённый snapshot и перечитывай состояние при необходимости. Ошибка записи оставляет старый сохранённый режим и видимый черновик с повтором.
5. Добавь **«Настроить под себя»** с группами отдельных функций, раскрываемыми по запросу. Ручные поправки отправляй частичным `background`, например `{"activityMode":"custom","background":{"kiraLife":false}}`. Пропущенные флаги сохраняются. Готовый режим и `background` нельзя смешивать в одном PATCH. `custom` без изменений ничего не записывает. Сервер выводит текущий режим из набора, поэтому ручной набор, совпавший с готовым, может снова иметь его название.
6. Оставь отдельную **«Приостановить фоновый AI»**: PATCH `{"budgetMode":"maximum"}` включает паузу, `{"budgetMode":"normal"}` снимает её, не меняя выбранные функции. Объясни, что применение готового режима возобновляет AI-фон; обычные напоминания, включённые дайджест и непрочитанные могут работать без AI. `activityMode=maximum` и `budgetMode=maximum` — разные поля с разным смыслом.
7. Показывай `enabled`, `effective` и `blockedBy` корректно: сохранённый выбор может ожидать Telegram или зависимость. Учитывай имеющийся account snapshot (`autonomousAiEnabled`, согласие/ограничения аккаунта), если он доступен: выбор режима не выдаёт согласие на обработку данных, credentials или центральное разрешение автономности. Не выдавай локальное `effective` за подтверждение фактического исполнения. Качество моделей остаётся отдельной настройкой.
8. Сохрани изоляцию account/server: после logout, смены сервера или аккаунта старый GET/PATCH не обновляет новый экран. Не стирай ручной черновик поздним фоновым обновлением. Проверь iPhone и iPad, светлую/тёмную темы, Dynamic Type, VoiceOver, состояния загрузки, отсутствия сети, ошибки записи и восстановления.

## Проверки и результат

Добавь синтетические DTO/API/ViewModel-регрессии: полный каталог и старый ответ без новых полей; неизвестный ключ; применение одного preset одним PATCH; частичный custom; снятие/возврат паузы без потери флагов; отсутствие Telegram; запрет показа неподтверждённого успеха; отсутствие записи при GET; сохранение черновика и игнорирование позднего ответа старого аккаунта. Fixtures не должны содержать реальные токены, людей, диалоги или снимки комнаты.

Запусти `swift test --package-path Packages/KiraCore` и интегрированную сборку приложения согласно локальным инструкциям. Проверь интерфейс в Simulator на iPhone/iPad с увеличенным текстом; физическое устройство и живое исполнение фоновых задач опиши отдельно от синтетических проверок. Не меняй модели персонажа, AR, auth-контракт или фоновые права ради этого экрана.

В отчёте владельцу укажи ветку/коммит, затронутые экраны и DTO, пройденные проверки и оставшиеся проверки на устройстве. Не публикуй в App Store и не меняй live-настройки аккаунта без соответствующего поручения.
