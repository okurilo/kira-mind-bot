# Смена ID Telegram-группы

Telegram при преобразовании обычной группы в супергруппу выдаёт новый chat ID. Права администратора в новой группе не восстанавливают возможность отправки на старый адрес.

`services/telegramChatMigration.ts` устанавливается на общий grammY API и middleware до session/auth/mention-фильтров. Подтверждённые пары принимаются из полей `migrate_to_chat_id`/`migrate_from_chat_id` служебного сообщения либо `parameters.migrate_to_chat_id` отказа Bot API с кодом 400. Имена групп не используются для сопоставления. Числовые ID проверяются на отрицательное безопасное целое.

Пары хранятся в `bot_settings` под `scopedBotKey('telegram:chat-migration:' + oldId)`; значение — строка нового ID. Транзакционная advisory-блокировка исключает конфликтующие пары и циклы. Разрешение ограничено восемью узлами; локальный кеш живёт пять секунд. Перезапуск не теряет адрес.

Новые отправки, copy/forward и чтение метаданных используют конечного получателя. После явного отказа с новым ID разрешён только один повтор. При сетевом сбое, 429/5xx или неизвестном исходе повтор не добавляется. Загрузки `InputFile` после отказа не повторяются: поток мог быть прочитан; адрес сохраняется для следующей свежей операции.

ID сообщений и тем относятся к исходному чату. Edit/delete/pin, отправки с reply/thread, `from_chat_id` и source message IDs не перенаправляются. Сессии, история и источники наблюдений с их курсорами не переписываются.

Наблюдения разрешают адрес **получателя** при чтении и сохранении настроек. Успешная доставка после миграции сохраняет обычный cooldown и watermark, без сообщения о недоступности владельцу. Старое событие автоматически не воспроизводится.

Chat registry сохраняет историческую запись. Новая запись, если отсутствовала, наследует политику того же чата; уже существующие настройки назначения не перезаписываются. Выбор чата скрывает исторический дубль при наличии новой записи; обращения к настройкам по старому адресу разрешаются к новому.

Регрессии: `tests/telegram-chat-migration.test.ts` проверяет транспорт, служебные updates и полный watcher poll с синтетическими данными, `tests/telegram-chat-migration-postgres.test.ts` — reconnect, атомарность, циклы, настройки и registry на одноразовом PostgreSQL (`KIRA_PLATFORM_TEST_PG_PORT`). Telegram-сообщения при проверках не отправляются.
